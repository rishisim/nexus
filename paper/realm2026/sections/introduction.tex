\section{Introduction}

Financial QA requires evidence selection, arithmetic, and careful handling of
entities, periods, signs, and units. Iterative language-model agents appear well
suited to these demands: they can search, inspect evidence, and revise an answer.
Each extra step, however, consumes tokens and latency and can introduce a new
retrieval, arithmetic, or formatting error. The relevant deployment question is
therefore not simply whether an agent can answer, but when its additional
computation is worth paying for.

We study a necessary precondition for selective agency: \emph{expert
complementarity}. A router can improve an accuracy--cost frontier only when its
expensive branch supplies enough unique correct answers. We isolate this issue
under controlled evidence. Every system receives the same leakage-audited
benchmark corpus and tools, so differences reflect orchestration rather than
access to different documents. A pre-generation gate chooses between a static,
one-call workflow and bounded ReAct using only target-independent question and
evidence features.

Our prespecified development study spans five financial-QA datasets, five
systems, and provider-level telemetry. On the official evaluation, ReAct was
the least accurate and most expensive primary system; the fallback gate routed
too broadly and failed its locked quality--cost criterion. We honored the stop,
then ran a separately frozen second-family replication on new development
evidence without executing the final partition. It repeated the configured
Static-over-ReAct ordering. A trace audit also exposed an important qualification:
method-specific answer contracts interact with the conservative scorer, so the
official unique-success counts are not a semantic error adjudication. The
contribution is an auditable warning rather than a successful router or a
universal claim against agents: establish both measured complementarity and
evaluation-contract fairness before training a difficulty router or spending a
confirmatory test set.
